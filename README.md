# Roll Call

A class attendance web app. The **Super Admin** creates **Class Rep** accounts, each Class Rep uploads their department's student list and starts GPS-fenced sessions in the lecture venue, and **Students** check in from their phones. Attendance exports with **students as rows** and **weeks as columns**.

## Account Roles

1. **Super Admin (`/admin`)**
   - The very first account created on `/rep/login` becomes the **Super Admin**.
   - Once the Super Admin exists, public sign-up is locked at the database level (`on_auth_user_before_created` trigger).
   - Only the Super Admin can create, suspend, or delete **Class Rep** accounts.
2. **Class Rep (`/rep`)**
   - Signs in with the email and password generated by the Super Admin (no email confirmation wait).
   - Creates classes, imports student rosters (`.csv`, `.xlsx`, `.xls`), starts GPS check-in sessions, and downloads vertical weekly attendance sheets.
3. **Student (`/join/:code` and `/me`)**
   - Claims their account once by entering their **Matric Number** and **Full Name** as uploaded by their Class Rep.
   - Bound to their phone via anonymous auth so one phone cannot check in for multiple students.

## Setup (5 minutes)

1. **Create a free Supabase project** at https://supabase.com/dashboard.
2. **Run the database migration:**
   - Open **SQL Editor** in your Supabase dashboard.
   - Paste the contents of [`supabase/migrations/0001_init.sql`](./supabase/migrations/0001_init.sql) and click **Run**.
3. **Enable Anonymous Sign-Ins:**
   - Go to **Authentication → Providers → Anonymous Sign-Ins** and toggle it **On**.
4. **Configure local environment:**
   ```bash
   cp .env.example .env.local
   ```
   Fill in `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` from **Project Settings → API**.
5. **Run locally:**
   ```bash
   npm install
   npm run dev
   ```
6. **Create your Super Admin account:**
   - Open `http://localhost:5173/rep/login`. Because no Super Admin exists yet, it will show **"First-time setup: Create Super Admin account"**.

## Keeping Supabase Awake (Cron Job / UptimeRobot)

On the Supabase Free Tier, projects pause after **7 days of zero database activity** (e.g., during holidays or exam breaks). Note that pinging your frontend homepage alone only hits Vercel/Cloudflare and **does not** wake Supabase.

This project includes a database keep-alive RPC (`public.ping()`) and two ways to trigger it automatically:

### Option A: UptimeRobot or cron-job.org (Recommended)
When deployed to Vercel, point a free HTTP(s) monitor at:
```
https://your-app.vercel.app/api/ping
```
- **Interval:** Every 6 hours (or once a day)
- [`api/ping.js`](./api/ping.js) calls `public.ping()` inside Postgres so Supabase stays active 24/7.

### Option B: GitHub Actions Cron (Built-in)
[`.github/workflows/keep-supabase-awake.yml`](./.github/workflows/keep-supabase-awake.yml) runs automatically every 3 days. Just add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` under your GitHub repo's **Settings → Secrets and variables → Actions**.
